# VibeTrack — OpenCode Rules

# These rules are ALWAYS applied when OpenCode assists with this repository.

## ⚠️ MANDATORY COMPLETION CHECKLIST

Every task MUST end with ALL of the following steps, in order, with no exceptions:

1. `node node_modules/.bin/prettier --write "src/**/*.{ts,tsx}" "App.tsx"`
2. `node node_modules/.bin/eslint . --ext .ts,.tsx --max-warnings 0` — fix every error before continuing
3. `node node_modules/.bin/jest --passWithNoTests` — fix every failing test before continuing
4. `git add -A && git commit -m "..."` — commit ALL changed files
5. `git push origin main` — push immediately after commit, every single time

**Do not consider a task done until `git push` has succeeded and `git log --oneline -1` confirms the commit is on origin/main.**

---

## Project Identity

- This is **VibeTrack**: a React Native 0.74+ gesture-driven event discovery app.
- Package manager: **bun** (always use `bun` / `bun add` / `bun run`, never npm/yarn).
- Language: **TypeScript strict mode** — no `any`, no `@ts-ignore` without explicit justification.

## Architecture Conventions

- All source code lives under `src/`. Root-level `App.tsx` and `index.js` are entry points only.
- Path alias `@/` maps to `src/`. Prefer `@/` imports for cross-module references.
- State: **Zustand** slices in `src/store/`. Keep selectors (`selectXxx`) as standalone exported functions.
- Persistence: **react-native-mmkv** via `zustand/middleware/persist`. Only persist user-preferences, not transient UI state.
- Navigation: React Navigation **v6** **Native Stack** + **Bottom Tabs**. Keep `RootNavigator.tsx` the single source of truth.
- Styling: **NativeWind** (Tailwind classes) where practical; `StyleSheet.create` for complex or animated styles.
- Icons: **lucide-react-native** only — no other icon library.
- Animations: **react-native-reanimated** v4 (`useSharedValue`, `useAnimatedStyle`). No `Animated` from core React Native.
- Gestures: **react-native-gesture-handler** v2. Wrap screens that use gestures in `<GestureHandlerRootView>`.

## Environment / Secrets

- Secrets live in `.env` (gitignored). Access via `@env` (react-native-dotenv).
- `.env.example` must be updated when new env vars are added.
- **Never commit `.env`**, keystores, API keys, or Match certificates.

## Testing Rules

- **Always write unit tests** for: store logic, selectors, utilities, services, data validation.
- **Always write component tests** for new components using `@testing-library/react-native`.
- Test files live in `src/__tests__/` (mirroring source structure).
- Mocks for native modules live in `src/__mocks__/`. Register new mocks in `jest.config.js` `moduleNameMapper`.
- Run tests with: `node node_modules/.bin/jest --passWithNoTests`
- All tests must pass before committing. Do not skip failing tests.

## Code Style

- Functional components only. No class components.
- Named exports for components; default export for the primary export of a module.
- `React.JSX.Element` as the return type for all components.
- Prefer `useCallback` for all event handlers passed as props.
- Avoid inline object creation in render (causes unnecessary re-renders).
- No `console.log` in committed code — use a debug flag or remove before commit.

## Git / Release Conventions

- **ALWAYS commit and push to `main` when a task is complete. No exceptions.**
- The full sequence before every commit:
  1. Run prettier (auto-fix)
  2. Run eslint (zero warnings/errors)
  3. Run jest (all tests pass)
  4. `git add -A && git commit && git push origin main`
- Verify push succeeded: `git log --oneline -1` should show the commit on origin/main.
- Version tags trigger CI/CD: `v1.2.3` format.
- GitHub Secrets required for iOS: `APPLE_ID`, `APP_STORE_CONNECT_TEAM_ID`, `DEVELOPER_PORTAL_TEAM_ID`, `MATCH_GIT_URL`, `MATCH_PASSWORD`, `APP_STORE_CONNECT_API_KEY_JSON`, `MAPBOX_ACCESS_TOKEN`, `PREDICTHQ_API_KEY`.
- GitHub Secrets required for Android: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `GOOGLE_PLAY_JSON_KEY`, `MAPBOX_ACCESS_TOKEN`, `PREDICTHQ_API_KEY`.

## Debugging Preferences

- Prefer explicit `testID` props on interactive elements for testability.
- Keep `__DEV__` guards around debug-only logging.
- Mapbox token is provided via `.env` — never hardcode tokens.

## Maps

- `@rnmapbox/maps` with Mapbox token from `@env`.
- Dark map style (`MapboxGL.StyleURL.Dark`) matches the app theme.
- Test files mock `@rnmapbox/maps` via `src/__mocks__/@rnmapbox/maps.ts`.
